## 三、不可回归的基础能力

以下能力属于稳定底座，不因三阶段工作流调整而改变。

### 3.1 项目保存与数据恢复

- 自动保存使用最新状态快照，避免并发保存用旧 revision 覆盖新修改；
- 页面隐藏或关闭前尝试刷新未保存状态；
- 保存失败或服务离线时不离开当前画布；
- 项目保存与恢复保持图片节点、批注、版本引用、文字卡和任务关系；
- 未登记资产不能写入项目；
- 项目地址刷新后保持当前项目，返回项目列表时清除项目标识；
- 原始资产只读，生成结果形成新版本；
- 删除画布节点不删除原资产，子节点解除失效父引用；
- 旧项目迁移不得丢失图片、批注、任务、文字卡和父子版本。

主要保护测试：

- `project-state.test.ts`
- `project-navigation.test.ts`
- `project-route.test.ts`
- `server.test.ts`

### 3.2 撤销、重做与画布交互

- `Ctrl+Z`、`Ctrl+Y` 和 `Ctrl+Shift+Z` 正确恢复有限历史；
- 撤销后产生新编辑时丢弃旧重做分支；
- 输入框、可编辑区域和组合键不会误触发删除或画布快捷键；
- 方向键微调图片或批注，`Shift` 支持较大步长；
- 中键拖动画布时文字卡同步移动；
- 鼠标在窗口外松开时结束文字卡拖动或画布漫游；
- 批量框选支持反向拖动和空白处起框；
- 图片浮动工具栏保持在可见安全范围。

主要保护测试：

- `canvas-history.test.ts`
- `canvas-input.test.ts`
- `text-card-pan.test.ts`
- `marquee-selection.test.ts`
- `canvas-layout.test.ts`

### 3.3 图片显示、布局与内存控制

- 导入大图等比缩小，不放大小图；
- 调整显示比例只改变图片框，不改变源图像素；
- 图片框裁切采用居中 `cover`，不修改源图；
- 生成图显示尺寸与元数据不同时，以实际解码尺寸计算；
- 横向、纵向整理使用各图片实际尺寸，避免重叠；
- 生成结果固定放在父图右侧并记录父版本；
- 大量图片使用可见区域加载和有限缓存；
- Blob Object URL 在离开画布时释放，避免长期内存累积。

主要保护测试：

- `canvas-layout.test.ts`
- `canvas-math.test.ts`

### 3.4 任务状态、严格串行与恢复

- 同一时间只允许一个活动任务；
- 已提交任务不能回退到附件上传或准备提交状态；
- 先在服务端记账 `submitted`，再点击网页提交按钮；
- 服务重启后恢复未完成任务、已提交时间和任务锁；
- 人工接管跨服务重启恢复；
- 用户可以结束已经提交的本地任务跟踪，并继续下一任务；
- 已提交到 ChatGPT 的内容不能被本地取消操作误报为已撤回；
- 文字任务可以只保存文字结论并完成，不要求图片结果；
- 任务完成前重新核验结果文件大小和 SHA-256；
- 文件被修改时保持 `collecting`，进入恢复状态；
- 同一 SHA-256 结果去重，不重复写入或回收。

主要保护测试：

- `task-store.test.ts`
- `protocol.test.ts`
- `canvas-automation.test.ts`

### 3.5 自动回收与重复提交保护

- 任务完成后只回收尚未返回画布的结果；
- 生成中、正在回收或已经全部返回时不重复回收；
- 历史图片基线只保存哈希并过滤重复源地址；
- 页面事件必须来自同一任务和同一绑定标签页；
- 只有非终态任务和明确的 ChatGPT 标签页可以主动重绑；
- 自动自愈绑定只适用于正在打开页面的任务；
- 旧扩展版本被拦截，当前最低兼容版本由测试固定；
- 图片任务在正式结果返回前显示生成占位，真实节点返回后隐藏。

主要保护测试：

- `canvas-automation.test.ts`
- `background-guards.test.ts`
- `page-state.test.ts`
- `build-output.test.ts`

### 3.6 登录、验证与浏览器安全

- 只识别合法 ChatGPT HTTPS 页面；
- 自动任务只接受固定本地画布来源；
- 登录或网页验证需要人工处理时才将 ChatGPT 切到前台；
- 普通结果解析失败不应无故抢占前台；
- 页面状态不确定时暂停，不重复提交；
- 不读取 Cookie、密码、ChatGPT 登录凭据或认证 Token；
- 本地服务只监听 `127.0.0.1`；
- HTTP 接口校验本地 Token 和允许的 Origin；
- 诊断输出不得泄露本地桥接 Token；
- 静态服务和资产读取阻止路径越界。

## 四、阶段一、阶段二测试缺口与补齐要求

当前阶段一、阶段二没有端到端或完整业务行为测试，现有局部单元测试对版本升级的业务对照价值有限。V3 开发不得把这些未覆盖行为误写成“已有自动化保护”。

在修改对应流程前，应优先建立最小行为刻画；确实难以自动化的内容，必须形成带输入样例、操作步骤和预期结果的人工回归记录。

### 4.1 阶段一最低行为基准

- 单个视角只输入一张用户选定的 D5 视角图；
- 不执行同角度多图候选比较；
- 多个不同视角分别创建任务和文字结果；
- 可选 SU 截图只服务于对应 D5 视角的可见细节判断；
- 返回主要问题和明确调整动作，包括焦距、构图、相机高度、俯仰和可见 SU 细节；
- 阶段一只返回文字，不发起生图；
- 可以直接进入阶段一，不依赖其他阶段状态。

### 4.2 阶段二最低行为基准

- 可以跳过阶段一直接导入图片进入阶段二；
- 明确区分结构底图与可选风格参考图；
- 提示词生成与效果图生成是两个独立动作；
- 未经用户明确发起不得自动生图；
- 目标图用于指导 D5 深化，不作为结构依据或最终交付图；
- 多个视角保持独立任务、独立结果和独立追溯关系。

### 4.3 旧规则到 V3 的待建测试映射

下表是 V3 应补充的测试目标，不代表当前已经存在对应自动化测试。

| 旧测试或规则 | V3 等价保护 |
|---|---|
| 阶段一把三个候选视角组成同一个文字任务 | 前置阶段每张 D5 视角生成独立 item 和独立文字卡 |
| 阶段二固定 D5 与 SU 角色 | 前置阶段每个 item 固定一张 D5 主图和可选配对 SU 图 |
| 阶段三为每张底图附带同一风格参考 | 优化阶段每张结构底图独立处理，并可复用共同风格参考 |
| 固定九张工作流提示词卡 | 三阶段模板数量按新规则更新，但结构保护和动作边界测试必须保留 |
| 阶段四玻璃整图 | 最终阶段仍只输入最终 D5 完整图，并保持比例、裁切和结构 |
| 正式归档固定写入 AI 目录 | 改为用户指定文件夹批量导出，同时保留不覆盖、顺延命名、去重和日志 |
| 单一 `selectedVersionId` 推断阶段 | 改为三阶段独立状态槽位，同时保留可验证关系优先、人工覆盖优先 |

补齐测试时，提交说明必须写明：新增测试名称、用户需求依据、保护的行为和仍需人工验证的部分。

## 五、三阶段升级的回归策略

### 5.1 修改原则

- 现有底层模块优先复用，不为阶段改名重写任务存储、资产仓库、结果回收或浏览器绑定；
- 新三阶段逻辑优先通过适配层、迁移器和新增字段实现；
- 不使用 `git reset --hard`、`git checkout --` 或清理命令覆盖当前工作区修改；
- 当前未提交修改属于现有工作成果，开始实施前必须先确认并建立可恢复基线；
- 原有测试不得为了新版通过而降低断言强度；
- 业务语义改变的测试必须先增加 V3 等价测试，再移除旧断言；
- 项目 schema 迁移先备份或创建快照，失败时保留旧项目原文件；
- 任何导出仍遵循不覆盖和可恢复原则。

### 5.2 实施前基线动作

1. 保存 `git status --short` 和 `git diff --stat`；
2. 在用户确认后建立基线提交或可恢复补丁；
3. 运行 `npm test`；
4. 运行 `npm run test:canvas`；
5. 记录测试数量、版本号和构建产物；
6. 为阶段一、阶段二建立最小行为刻画测试；暂时无法自动化的行为保存人工回归记录；
7. 使用真实项目副本验证项目打开、保存和恢复；
8. 对项目资产、版本和父子关系生成校验报告。

### 5.3 每个开发阶段的准入条件

```text
类型检查通过
→ 共享协议、桥接、扩展测试通过
→ 画布测试通过
→ 旧项目迁移测试通过
→ 新三阶段专项测试通过
→ 人工完成核心功能冒烟测试
```

任何一步失败，不得继续覆盖或迁移正式画布项目。

### 5.4 发布前必须执行

```powershell
npm test
npm run test:canvas
npm run fixture:release -- <旧项目副本路径>
npm run verify:release -- <隔离验收样本路径>
npm run package:release
npm run smoke:release -- <已解压发布包路径>
```

发布包冒烟测试必须在独立临时 runtime 中运行，不使用正式项目数据。

## 六、人工冒烟检查清单

### 项目与保存

- 创建空白项目；
- 创建带 Markdown 项目；
- 导入图片后刷新页面，数据仍在；

- 打开旧项目副本，图片、文字卡、批注和版本关系完整。

### 画布交互

- 导入多张大图，缩放和漫游流畅；
- 撤销、重做和撤销后新编辑正常；
- 中键漫游、框选、键盘微调和删除不误触；
- 整理图片不重叠，源图尺寸不改变；
- 结果节点位于父图右侧并保留连线。

### 任务与结果

- 文字任务返回文字卡，不要求图片；
- 图片任务显示占位并只回收一次；
- 一个任务运行时不能创建第二任务；
- 登录或验证异常时暂停并可人工接管；
- 结束本地任务后可以创建下一任务；
- 服务重启后活动任务和提交锁恢复。

### 三阶段专项

- 多个不同视角分别创建前置文字任务；
- D5 与 SU 截图一对一配对；
- 可跳过前置阶段直接进入优化阶段；
- 可直接导入最终 D5 进入最终阶段；
- 最终玻璃图比例异常时暂停；
- 只导出用户选定版本，目标目录已有文件不被覆盖。
