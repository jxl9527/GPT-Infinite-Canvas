## 3. 功能A：点击生成图，滑动查看区别

### 3.1 交互约定

- 在选择工具下，单击已生成图片主体，松开后进入大图对比浮层。保留双击入口和选中工具栏“与原图对比”入口。
- 单击判定建议移动不超过5个屏幕像素；拖动图片、中键、空格平移、手形工具、框选、Shift/Ctrl 多选、缩放手柄不打开浮层。先完成手势判断再触发，不能在按下瞬间打开。
- 普通导入图片仍按现有规则选择和预览；文字双击编辑保持不变。锁定的生成图仍可查看。
- 浮层以图片为主体，左侧“本次底图”，右侧“生成结果 · V编号”。垂直分界线默认50%，圆形左右箭头手柄；左右拖动到0%或100%分别查看完整一侧。
- 上方保留名称、版本切换、适合窗口、100%与关闭。对比浮层打开时，画布快捷键和滚轮事件不能穿透；关闭恢复原画布视口、选择与焦点。
- 支持鼠标、触控和键盘方向键调整滑块，Home/End 到两端；Esc 关闭，Tab 焦点限制在浮层内。指针离开图片或窗口失焦后不得留下拖动状态。

### 3.2 原图配对和真实尺度

“本次底图”严格取生成版本的 parentVersionId，通过版本→资产引用加载；禁止按名称、画布邻近位置或最新导入图猜测。同图再次生成的兄弟版本都对应同一底图。以生成图继续修改时，默认对比直接父版本，可另提供“最初原图”切换，并显示基准名称。

onPreview 改传明确的 versionId 或带该字段的预览上下文。资产可能按内容去重，因此 assetId 不能作为版本身份。删除底图的画布节点后，只要版本/资产仍保留，对比必须可用。历史数据缺少或断裂父引用时，退回单图预览，明确“缺少对比底图”，不猜配对。

两张图放在同一个固定完整画幅中，仅改变结果层的裁剪遮罩；不要随着分割比例改变图片元素宽度而重新缩放。同步缩放、平移共享同一变换，滑块只控制可见范围。

同比例但不同分辨率：按完整画幅等比对齐。异比例：不拉伸、不裁切、不自动形变配准；在共同视口中分别完整等比居中，空白区保留，提示“画幅比例不同，仅作完整画面对照”。对比是发现结构漂移的工具，不能通过自动对齐掩盖建筑位移。

只加载当前一对图片；可先用预览图，再替换高清图。关闭、切换版本后释放不再使用的资源。加载中、失败、重试均提供明确状态，不同时解码所有历史版本。查看状态不进入项目撤销栈。

视觉来源：[用户指定的 OpenAI 说明页](https://openai.com/zh-Hans-CN/index/introducing-chatgpt-images-2-5/)。公开正文已读取；滑块外观按用户附件理解，本轮未实测官方组件，也不要求复刻其内部实现。

## 4. 功能B：同图、同提示词独立生成多个版本

### 4.1 用户界面

生成面板新增“每张图生成：1 / 2 / 3 个版本”，默认1；与“同时生成：1 / 2 / 3 个任务”分开设置。例如选择2张、每图3版、并发3，显示“共6个任务，最多3个同时生成”。提交前直接显示总数，不增加多余确认弹窗。

批次运行中，每条任务提供“同样设置再生成1版”，无需等第一版完成。点击后沿用该任务保存的底图和提示词，追加独立任务；不得读取正在编辑的提示词草稿，也不得把刚生成的图片误当新底图。提交期间短暂禁用以阻止一次点击被重复处理，保存完成后允许再次有意追加。

现有“重新生成”需消除歧义：复用相同输入的按钮叫“同样设置再生成”；选中结果作为新输入则叫“以此图继续修改”。失败任务的“检查网页/恢复跟踪”与“新建一次生成”分开，不能以恢复名义再发送。

活动批次内只追加与其冻结提示词一致的任务；改了草稿不修改正在执行的任务。不同提示词的新批次仍按原规则等待当前批次结束，本期不扩展多批次同时调度。暂停中可以追加但保持排队；明确停止后不自动重启，待已发任务处理结束再建新批次。

### 4.2 任务与版本模型

每个生成尝试独占现有 item.id；同一 sourceVersionId 可对应多个 item。继续使用 batchId+itemId 作为请求幂等身份，taskId 作为实际任务身份。每次网络重试复用原 item.id；只有用户主动新增一次生成才创建新 item.id。

建议增加兼容字段：偏好 copiesPerImage、任务项稳定显示序号 variantOrdinal，以及可选 clonedFromItemId/retryOfItemId。字段命名由实施者结合代码确定，但身份原则不可改变。序号在入队时分配并持久化，按同一父版本已有编号继续增长，不按回图先后或现存节点数量命名。

先将新增 items 保存成功，再允许服务端创建任务；保存失败不派发。追加操作与轮询更新必须基于最新项目版本合并；保存冲突沿用现有冲突草稿保护。一次追加请求重试不能再增加一组 items，需复用该次操作预分配的 item IDs。

失败重试建议新增任务项并引用原项，保留旧失败记录，不再覆盖原项身份。若失败前可能已发送，优先恢复跟踪；用户主动补生则作为新的独立尝试保留两条记录。

初始队列建议按轮次排列 A1、B1、A2、B2，避免某张图长期等待；后续追加放队尾。每批总任务上限沿用200，但按展开后的数量计数：例如100张×3版超限应明确提示，不静默截断。

### 4.3 画布结果

同图各任务使用独立占位位置和编号。目前 SimpleCanvas 占位只按已完成兄弟结果算位置，同图重复任务会重叠，必须一起修正。根据 item 顺序分配占位槽，回图替换对应槽；乱序完成不得占用另一任务位置或覆盖用户移动的已完成节点。

回图仍通过 task.simpleRender.itemId → sourceVersionId 定位父版本，以 taskId+resultId 防止重复插入。同样内容可以复用底层资产文件，但必须保留每次生成的独立版本、任务记录和显示名称。一次任务返回多图时用子序号，不丢弃附加结果。

## 5. 功能C：三个任务并发

增加“3个任务”可选档位。默认继续为已验证的2个，用户选3后持久保存；本需求授权提供三任务能力，不等于要求强制默认3。旧项目1/2设置原样保留。

上传、填提示词、点击发送仍依次进行；确认上一任务已提交后再准备下一项，最多三个任务在生成/回收过程中重叠。每项独立 ChatGPT 网页和绑定，不在同一对话连发三次，不用并行 DOM 点击冒充并发生成。

同时更新共享类型和解析、前端偏好/批次、项目校验、任务容量及显示文案。搜索全部硬编码的1/2限制，逐处判断，不全局替换数字。服务端保持互斥容量检查作为最终限制；queued/opening 等已占槽任务也计入，不能出现“3个生成+第4个正在发送”。

每个标签页只能收本任务消息。绑定检查继续约束 project/task/tab/nonce；禁止从全局最近任务覆盖其他标签页。三任务下复核已有 nonce 自愈，保留 binding-diagnostics，日志不写连接令牌。网页刷新或扩展重载先恢复观察已提交任务，不能自动重新点击发送。

有任务 needs-user、无法确认是否提交、账号限流或绑定异常时，暂停后续派发并提示具体任务；其他已发任务继续观察回收，不能让整批因为一项异常丢图。用户恢复后仅派发尚未发送的项。并发档位本期沿用“活动批次中不可更改”，下一批再切换，避免服务端快照和任务身份不一致。
