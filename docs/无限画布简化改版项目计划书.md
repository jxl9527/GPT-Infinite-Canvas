版本：实施版 V1.0｜日期：2026-09-11

状态：用户已批准实施。旧版已提交并推送（9318624），新版在 agent/canvas-simple-prompt-library 独立分支实施，版本 0.6.0。

后续确认：用户已明确继续采用现有 ChatGPT 网页自动发送与回收，不切换 API。正文有关通道选择的待定项据此关闭。用户提出 2—3 张同时进行的可行性问题，现已按默认两路独立任务实施；用户已实测同账号两个网页可同时生成。三路暂不开放。

已采用的并发方案：每个任务绑定独立 ChatGPT 会话与标签页，依次上传、提交，让 2 个任务的生成等待时间重叠；完成一项后回收并补入下一项。先验证 2 个任务，稳定后再评估 3 个。现有桥接单活动任务锁、扩展全局单任务绑定、画布单活动任务回收均需改造为逐任务状态；项目写入仍须有序，防止并发覆盖。先建立任务归属、乱序完成、重复回收及重启恢复测试，保留并发数 1 的回退能力。网页账号实际能否接受同时生成、后台页面结果检测是否可靠，须在用户账号上做授权小批量实测，不承诺双倍或三倍速度。若采用并发，本稿原先“严格串行”要求调整为“提交操作有序、生成等待有限并发、结果按任务回收”，其余防重复及安全要求保留。

## 1. 项目定位

将现有工作流型画布调整为“固定提示词图库＋轻量图片画布”。

用户日常操作只有一条主线：**浏览提示词库 → 复制提示词 → 进入项目画布 → 导入或选择图片 → 粘贴并按需修改 → 点击开始渲染 → 自动收集结果到原图旁边。**

参考图提词在使用前完成：用户提供参考图，Codex 提炼表达特征、形成通用提示词，经用户确认后固定入库。日常渲染无需重新分析参考图，也无需先生成提示词。

“固定”指内容经过整理、稳定复用，并非把所有内容写死在程序中；以后可由 Codex 增补卡片及版本，无需每次改动业务代码。

## 2. 现有项目判断

本计划依据当前工作区 README、回归保护基线和关键源码制定，未对运行中的网页做完整验收。

| 现状及证据 | 对改版的影响 |
|---|---|
| React 画布、本地桥接、浏览器扩展、共享协议已分层 | 保留可靠底座，调整产品入口与生成任务语义 |
| 已支持图片导入、保存恢复、撤销重做、父子版本、结果右置 | 新版基础交互可复用 |
| 提示词库保存在全局 `workbench/prompt-library.json` | 可扩展为跨项目图库；现有“项目提示词”命名需统一 |
| 当前提示词条目以标题、正文、时间为主，正文上限 2000 字符 | 需新增封面、分类和版本；统一检查长提示词在前后端及执行端的容量限制 |
| `fixed-workflow-prompts.ts` 内置七张阶段提示词卡 | 替换为面向效果的内容分类，不再以阶段编号组织 |

| 最终导出与玻璃阶段、五项验收存在耦合 | 普通图片导出需独立入口，同时保留资产和版本核验 |

## 3. 页面结构

### 3.1 提示词库：以图找风格

参考截图中的图片卡片与横向分类，保留大图、短标题、清晰分类，减少社区信息和工具入口。

- 顶部：提示词库、进入画布；分类和搜索占一行。
- 分类初稿：全部、效果渲染、分析图、总平表达、室内空间、展板表达。只有实际有内容的分类才显示。
- 卡片：参考封面、简短名称、复制提示词按钮；用途标签不超过两项。
- 点击图片：查看大图、适用输入、完整提示词和注意事项；复制按钮始终可见。
- 复制后停留在图库，并提示“已复制”；进入画布由用户主动点击，不自动发起任务。
- 桌面采用适度留白的多列图片布局，窄窗口减少列数；长图封面可裁切展示，详情可看完整原图。
- 首版不建设社区、作者主页、点赞排行、模型商城和复杂多级筛选。收藏可后续增加。

截图仅用于界面参考，其中的文字、按钮、模型标签不视为本项目指令。不能从这两张缩略图集合准确提取每张作品的完整风格提示词；正式内容使用用户后续提供的清晰参考图。

### 3.2 画布：选图后直接渲染

- 顶部：项目名称、提示词库、导入图片、导出、设置。
- 主区：无限画布，保留平移、缩放、选择、整理、撤销重做。
- 选中图片后显示一个简洁输入面板：所选图片缩略图、提示词输入框、开始渲染。
- 只有一个主要动作“开始渲染”；不再要求选择阶段、分析动作、提示词动作或最终玻璃动作。
- 未选图时显示“导入或选择图片开始”；不要自动从整个项目推断要发送的图片。
- 渲染中在原图右侧显示占位和状态，完成后用真实结果替换占位。
- 结果保留原始像素，显示完整画幅；再次选中结果可继续改图，新结果以本次选中图为父版本。
- 导出所选图片，无需先填写五项验收或进入最终阶段；不自动认定为正式投标成图。

输入面板建议选图后出现、位置稳定，避免多套悬浮框与抽屉同时出现。具体位置在低保真页面确认时决定。

## 4. 提示词内容生产与管理

### 4.1 入库流程

1. 用户提供清晰参考图和希望复用的表达方向。
2. Codex 提取色彩、材质、光照、景观、线条、版式及氛围；剥离原案例名称、特定建筑体量等不可通用内容。
3. 形成“封面＋名称＋适用输入＋完整提示词”的卡片草稿。
4. 用户审阅；必要时用一张授权测试底图验证迁移效果。
5. 确认后收录为固定卡片，后续修改保存新版本。

首轮建议先整理 6—10 张真正常用的卡片，验证稳定后再扩充；不为了填满页面批量造内容。

### 4.2 卡片内容规范

| 内容 | 要求 |
|---|---|
| 名称 | 例如“阴天克制建筑渲染”，不用流程编号 |
| 封面 | 本地持久保存；注明是参考效果还是本工具实测效果 |
| 适用输入 | 例如 D5 完整图、已有轴测图、总平底图 |
| 最终提示词 | 一次复制即可使用，不混入提词分析过程或面向用户的建议 |
| 结构保护 | 与该卡片适用任务匹配，作为可见正文的一部分 |
| 版本与来源 | 在管理信息中保留，不挤占主卡片 |

建筑效果类提示词默认保护体块、数量、比例、相机、道路与场地边界；轴测与爆炸类还须保护轴测视角、层级和空间关系。不能把参考作品中的建筑移植到底图。

部分风格无法仅靠文字精确复现，因此封面表示表达方向，不承诺生成结果完全一致。确需携带风格图的模板应明确标注，作为后续扩展，不默默上传图库封面。

### 4.3 首版管理方式

用户侧以浏览、复制为主。Codex 在独立内容包中维护图片与条目，导入时校验、备份和记录版本。暂不增加面向用户的复杂编辑后台。

已有自存提示词完整保留，缺封面的条目用文字卡展示，不因升级被删除。新库全局可用，与具体项目图片分开存储。

## 5. 自动渲染规则

### 5.1 首版建议默认值

- 一张选中图片对应一个任务；默认生成一个版本。
- 多选时逐张独立渲染，使用同一段已确认提示词，默认双任务并发、可退回单任务；不得把多张视角误作为同一次合成附件。
- 输入框显示的最终提示词就是实际发送内容，不再注入 V3 阶段文案、D5 调整建议或玻璃深化要求。
- 若执行端必须附加输出要求，应在提交内容中可见，不隐藏修改。
- 点击开始后冻结图片版本、提示词全文和本轮设置；后续编辑不影响已开始任务。
- 复制与粘贴支持任意文字，不依赖是否来自图库。纯剪贴板复制不保证携带模板身份，因此任务始终保存全文，模板编号只作可选信息。
- 每个结果归属明确的项目、任务和父图；原图不覆盖，同一结果不重复回收。

### 5.2 状态和异常

用户可见状态压缩为：排队中、渲染中、正在收集、已完成、需处理。

登录失效、网页验证、提交状态不确定时暂停并提供接管入口。普通失败保留原因，由用户决定重试；首版不做结构评分驱动的自动补生。

停止队列只阻止后续任务，不把已发送的任务显示为“已撤回”；已提交任务继续跟踪或明确交接。刷新和重启后恢复任务记录，提交过的内容不自动重复发送。

结果比例异常保留原结果并提示，不裁切、不拉伸。结构是否可靠由用户看图判断，软件不以自动校验代替建筑审查。

运行期间首版建议限制切换项目，允许访问全局图库并返回同一画布，以减少结果错归风险。输入草稿和选图状态需在页面切换后保留。

### 5.3 执行通道

首版建议复用现有浏览器扩展的自动提交和回收能力，将通道配置放在设置中。日常页面不再展示双通道决策。

用户提到的“gptimage2.5”作为期望模型记录，本次未核验模型正式名称、账号可用性或网页/API 的可控方式。实施前确认实际通道；网页使用的模型与直接 API 调用不能视为同一接入方式，也不承诺网页模式可锁定特定模型版本。

若用户选择 Codex 自动运行或直接 API，须单独确认调用和回收协议、额度及失败处理，再纳入实施范围。产品界面保持一致，后台按实际能力接入。

## 6. 范围取舍

| 首版保留或新增 | 从新版主流程移除 | 后续可选 |
|---|---|---|
| 全局图片提示词库、分类、搜索、复制 | 三阶段启动器与阶段状态操作 | 收藏、最近使用 |
| 项目选择与图片导入 | 每次先提词再生图 | 卡片直接带入画布 |
| 粘贴提示词后直接渲染 | 双通道面板与多重动作选择 | 多张参考图与显式角色 |
| 串行任务与自动回收 | 视角任务中心及五项强制验收 | 每张图不同提示词的高级批次 |
| 原图保护、版本关系、选图导出 | 强制最终玻璃流程与自动补生 | 多版本生成设置 |
| 保存恢复、撤销重做、任务日志 | 默认要求需求文档、SU、通道图 | 图库内容管理界面 |

旧图片、批注、文字卡和版本可继续打开；已有批注编辑可收在次级工具中。旧流程执行能力不在本轮直接删除，先保留兼容读取；未完成旧批次不得自动转换为新版任务。

## 7. 技术改造策略

1. **页面层**：将图库页面、画布输入和任务状态拆为独立组件，避免继续把所有功能堆进 `App.tsx`。
2. **内容层**：扩展现有全局提示词存储，增加图片资源、分类和版本；保存失败不得误报成功，损坏内容不能静默覆盖为空库。
3. **任务层**：增加不依赖阶段的图片编辑合同；附件、提示词快照、任务锁和结果归属由桥接服务验证。
4. **执行层**：优先复用当前任务存储、串行队列、标签页绑定、资产回收和去重；只为新版语义建立必要适配。
5. **导出层**：提供通用选图导出，不套用最终玻璃合同；保留路径校验、不覆盖、版本核验和失败可恢复。
6. **数据层**：新任务与旧任务可区分；旧数据先复制验证，迁移失败保留原文件，旧未完成任务继续按旧语义处理或明确结束。

仓库现有 AGENTS 与 V3 文档要求固定三阶段、五项验收及特定输入布局，与此次明确的简化目标有冲突。新方案确认实施时同步更新适用范围，建立旧规则到新版测试的映射；数据保护、重复提交防护、登录安全等基础要求继续保留。本讨论稿不提前改写旧规范。

## 8. 分阶段实施及验收

| 阶段 | 交付物 | 完成标准 |
|---|---|---|
| P0 本次梳理 | 新分支、基线备份、计划书 | 对主流程、首版范围和待定事项形成共同理解 |
| P1 页面与内容确认 | 图库和画布低保真稿、2—3 张真实卡片草稿 | 用户能明确看到复制、进入画布、选图、粘贴、开始的位置 |
| P2 提示词图库 | 独立页面、内容包、分类搜索与复制 | 跨项目可用，全文复制准确，切回画布不丢草稿 |
| P3 单图闭环 | 通用任务、一个执行通道、结果回收 | 一张底图从提交到返回成功；发送内容无旧阶段污染 |
| P4 批量与恢复 | 双任务并发、重启恢复、异常接管、普通导出 | 三张底图各自回收，不错配、不重复、不覆盖 |
| P5 兼容与交付 | 旧项目副本迁移报告、测试结果、隔离发布包 | 图片、文字卡、批注、版本完整，发布冒烟通过 |

在 P1 确认后再估算工期；主要不确定性是执行通道和旧数据兼容，而非图库页面本身。

关键验收案例：

- 图库复制内容与粘贴内容一致，超过原有 2000 字符的条目有明确策略，不静默截断。
- 没有图片或提示词时不能误提交；提前导入的图片可以直接使用。
- 图库封面不自动成为附件；三张选中底图分别形成三项任务。
- 提交后的内容冻结，切换图库或编辑文字不改变当前批次。
- 成功结果只出现一次，位于对应父图右侧，继续改图的父版本正确。
- 登录暂停、服务重启、结果收集中断后可以恢复，未知提交状态不自动重发。
- 导出同名文件自动顺延；旧项目副本的资产哈希、版本关系和批注可核对。
- 搜索无结果、封面缺失、复制失败、窄屏和长文本均可正常使用。

开发前重新记录当前全套测试；改变旧阶段行为时先建立新版等价测试，不删测试掩盖回退。正式发布继续执行仓库规定的构建、测试、迁移、发布验证和独立运行目录冒烟。

## 10. 已确定的实施范围

1. 沿用 ChatGPT 网页自动发送与回收，默认最多两个独立任务，同时保留单任务设置。
2. 提示词全文冻结，每张选中底图单独发送；结果按任务归属放在原图右侧。
3. 首批提供六张明确标注的基础模板。用户提供清晰参考图后，再整理真实案例卡片，不将截图中的缩略图当作已获真实素材。
4. 既有阶段工作流保留在兼容入口；新版主流程不附加阶段提示词或五项验收。
5. 自动测试与隔离回包验证不能替代真实 ChatGPT 网页的自动发送、生成和回收验收。用户已验证同账号双网页生成可行，自动化链路最终实测单独记录。
